## Design Context

### Users
Developers and technical power users working quickly with JSON and color values. Their primary jobs are to paste or drop input, verify it, transform it, inspect it, and copy the result with minimal interruption. JSON inputs are typically snippets through files up to 5 MB; integers larger than JavaScript's safe range must remain exact.

### Brand Personality
Precise, utilitarian, restrained. The interface should feel like trustworthy technical documentation rather than a generic developer dashboard: dense where density improves scanning, quiet everywhere else.

### Aesthetic Direction
Use old NASA documentation standards as the foundation: strict hierarchy, numbered sections, technical labels, rules, registration-style metadata, and typographic discipline. Borrow the compact editorial/table density of Box Score and the whitespace and restrained navigation of Andrea.bio. Keep the ASCII character without turning every element into decoration. Support equally intentional light and dark themes.

### Design Principles
1. Put the working surface first; instructions and decoration must not compete with the task.
2. Prefer document structure, typography, spacing, and rules over cards, icons, shadows, or ornamental ASCII.
3. Make keyboard-first actions and current state immediately legible to power users.
4. Keep dense information aligned and scannable while preserving quiet space around major sections.
5. Preserve user data exactly, keep processing local, and remain responsive for JSON files up to 5 MB.
